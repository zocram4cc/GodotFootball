# PoseVeto: RE decode of the human-dodge gate (team+0x6a4, event kinds, window)

RE only. Tree = origin/main at 7cc9917 (veto stays). No code changes pending. VAs are image VAs (base 0x140000000). OBS = read from the decompile at the VA; INF(conf) = inference; "not decoded" means the VA is named but its body was not read.

Notation: `G` = `*(0x1436f3dc8)`; `MI` = `*(G+0x270)`; `MA` = `*(G+0x18)`; `T` = team record `FUN_140a48a30(G, side)`; `E` = match ctx `+0xe0` (event store); `gs` = `FUN_141e532d0()` = 54.

## 0. Answers

1. `T+0x6a4[slot]` is a per-player **reaction-delay countdown in PES frames**; player id = `side*11 + slot`. Written by `FUN_1405027A0`, `FUN_1404fdd20`, and a 10-frame floor in `FUN_140502190`. It counts down once per frame and is zeroed when the match is not in play. The human gate reads only `!= 0`.
2. The human gate is eligible **only if `T+0x255 == 0`** (team not in possession), `FUN_140a0b350` body 0x140a0b350-0x140a0b42d. `T+0x255` is "team in possession" (INF high, §2.4). GF's stand-in is `teamGateOpen = !IsInPlay()`, which never checks possession. This is the largest gap, and the likely cause of the 64% in-possession dodges measured with the veto off.
3. The window is **the team's newest ball event**: refuse if its team is mine and `MI.frame - newest.frame < gs*0.2` (10.8 frames). GF uses the player's own last touch in `ms/10` units, so its window is 10 units of 10 ms = 100 ms, against PES's 10.8 frames at 54 Hz (about 200 ms).
4. `FUN_140a6ce10` (busy) is true for kinds 9-14, and for kinds 6/7 with no carrier. GF records 4 kinds (`kTouch, kPass, kHighPass, kShot`, `pesreceive.hpp:89`), so GF has no structure for kinds 5-14. The busy test also feeds the reaction writers.
5. The roster-slot tail refuses only when `T+0x6a4[slot] != 0` AND busy. Without the countdown array and kinds 9-14 it is a no-op in GF. Porting it means building the array, its writers, and the kind structure (§7).

## 2. The human gate `FUN_140a0b350` (body 0x140a0b350-0x140a0b42d), in the decompiled order

1. Feature `FUN_141e5ca20(.., 0x27)` byte `+8` on. GF: on (`featureOn`).
2. Return 0 if the `G+0x3b0` object's state `func_0x14234e8e0 == 4`. GF: unmapped, stand-in true.
3. Side = `(10 < id && id < 22)`; `T = FUN_140a48a30(G, side)`.
4. `FUN_140a40bd0(T, caps)`, then `FUN_140a604d0(caps, 9)` (team capability bit 9, table not decoded), `func_0x140ca1a50(0x10)` (global capability 0x10) and `FUN_1406b4c10(pc+0x40, 0xe)` (anime class test). Any false: return 0. GF: stand-ins true.
5. `MI+0x116c == 2` returns 0. State 1 is in play (`FUN_140502190` 0x140502190 tests `== 1`). GF: `!IsInPlay()`-like.
6. `func_0x1404c8e60(MA, id)` returns a float that must be `<= _DAT_14253ee30` (100.0; the value is in the carrier and defence notes); otherwise return 0. The function is not decoded.
7. `FUN_140a638c0` (the team's role-0 player, defence doc `pes-re-defender-decisions.md`): if he is beyond `F[0x18]` in x and `|z| < F[0x1c]`, return 0.

10. **Roster-slot tail** (inside step 9): `slot = id % 11` (id < 22). If `T+0x6a4[slot] != 0`: `carrier = FUN_140a627e0(ctx, 0)`, `busy = FUN_140a6ce10(FUN_140a3e190(E,0), carrier < 22, 0)`; if busy return 0. Then return 1. OBS.

GF today (`elizacontroller.cpp` `_DodgeHumanCandidate`, `pesdodge.cpp` `HumanDodgeGate`): step 1 is `featureOn`; steps 2-4 and 6-7 are unmapped (stand-ins true); step 5 is roughly `!IsInPlay()`; **step 8 uses the player's own last touch (`/10`, 100 ms) and does not test the team**; **step 9 is replaced by `teamGateOpen = !IsInPlay()`**, which never tests possession; **step 10 is `rosterSlotValue = 0`**, so it never fires.

## 3. `team+0x6a4`: writers, countdown, callers

**Writer A, `FUN_1405027A0`** (0x1405027a0; args `(ctx, T, side, _, flagA, flagB, slotFilter)`). Runs only when `MI+0x116c == 1` and (`flagB != 0` or `T+0x255` clear).
