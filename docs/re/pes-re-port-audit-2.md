### H1 — `RecomputePesHolder` never sees the skip/arm phases it ports: stoppage ticks always read as "arm-and-run"

- GF: `Match::Process` (`match.cpp:849-853` on `origin/HolderSplit`): `pesRestartStep = (!IsInPlay() || GetRefereeBuffer().active) ? 0x0B : 0x16`, then `RecomputePesHolder()`. - Effect: bounded. W1 re-derives the holder from the newest ring-1 key; running it where PES would skip it only matters if the key changed during a skip phase AND the holder is read before the next arm/run phase re-runs it. The step handlers that own skip phases are Flow-side (placement/teleport), not key pushers (touch/key events push keys). But it is a real semantic gap, not a ponytail the code names: the call-site comment claims "The switch itself stays exact" while the *input* never exercises two of its three arms.
- Fix: name it. Extend the call-site ponytail to say the skip arm is unwired (no GF tick reads a skip phase; the switch's `default` is dormant until the per-value `O+0x728` writer lands per `pes-re-restart-step.md` §2/§7), OR drive `pesRestartStep` from the referee programme (stopped-but-not-armed → a skip value such as 9).
