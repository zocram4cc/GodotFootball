## 2. Where the clean boot stops now (CONFIRMED)

`FUN_14029E940`'s pool step `FUN_1403EA250(pool, 0x4000)` and `FUN_14037FF60` (lua_atpanic's wrapper, called from `FUN_14029DCE0`) tail-call into **VM-protected functions in `.impdata`**: `0x143E98DA0` and `0x143DFA780`. Their code is chains of obfuscated blocks joined by `push target; ... ret` jumps (survey targets 0x143E98E49, 0x146FD2707, 0x1567EBD4A, ...); the unicorn trace of each runs >20,000 instructions through dozens of scattered blocks and shared dispatcher blocks (0x154626EF0, 0x1478DD240 recur in both chains), and a zero-state emulation of either runs 150k (pool setter) and 1.26M (atpanic) instructions before fetching an OS function (0x6FFFF93F7520, kernel). They are not game logic; they are the packer's protection of two tiny API calls (set a pool's chunk size; set the Lua panic handler). Translating a virtualized function block by block is not tractable here (the block graph is data-dependent and enormous), and a model needs their real effect, which I could not extract in a zero state (they reach OS code first).

Decision needed from Main (I did not take it): the boot is clean only through PES's own code; these two functions are the first that are not translatable. Options, none done: (a) a named stand-in for each protected function with its effect read from a LIVE capture (the pool's chunk-size field and the Lua state's `panic` field: both are single stores in the live heap before/after the call: needs two hooks `0x143E98DA0` and `0x143DFA780`, any call, EVERY 20, cap 6, to see exactly what they write), (b) skip `FUN_14029E940` and give `FUN_14029DC60` a hand-built script manager (replaces more PES logic: not recommended), (c) a native x86 emulation fallback for the packer's section (a new dependency).
