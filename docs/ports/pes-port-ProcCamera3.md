## 1. The miss, and its root cause (CONFIRMED)

The report's two hypotheses were (a) an image-time slot read vs the snapshot, (b) a model mirror differing from machine code. It was neither; it was the translator. Chain of evidence:

1. `gdb` on the failing `snapdiff_141F7AE60` (recipe: `break pes_dispatch_missing`, `bt`): the first registry find (`0x141B55730` for `CAMERA_TARGET_0200`) already reaches `0x140421F40` (its not-found callback, `xor eax,eax; ret`; PES's own run never calls it, so the closure did not contain it).
2. Entry-register traces of every closure function in both runs (unicorn hook on PES bytes vs `gdb` breakpoints on `pes_fn_*`) show the same call sequence up to `0x141B70420` (the registry's tree search) with the **same key** string `CAMERA_TARGET_0200`, length 0x12 -- but the translated search key's hash word was **`0x2EF68831`**, where PES's tree holds hashes like `0x2839` (`CAMERA_TARGET_0201`). The hash is `0x141B70060`: `sum(c[i]*i)` (`0x2828` for `..0200`, recomputed in Python = PES's value) with an SSE loop guarded by `[0x14350B360] > 1` (isa level, 5 in the snapshot and in the image).
3. The generated `pes_fn_141B70060.cpp` contained `/*UNHANDLED PMOVSXBD xmm1, xmm0*/(void)0;` and `/*UNHANDLED PMULLD xmm1, xmm2*/(void)0;` -- xlate **silently** emitted a no-op for any mnemonic it had no semantics for.
4. Scope of the class: 15 committed layer files held the marker: PREFETCHT0 (no effect), PAUSE (no effect), `BSWAP` (3 files, pre_match), `PUNPCKLBW/WD` (1), `MAXSD` (1), `CVTDQ2PD` (5 sites in `0x140227D20`, a cutscene function), and two functions whose x87/OUT noise is dead decode (below).

## 2. What changed (all committed, `472a835a`)

- **`xlate.py`**: implemented `PMOVSXBD`, `PMULLD`, `PUNPCKLBW`, `PUNPCKLWD` (`do_packed_int`), `CVTDQ2PD`, `MAXSD`/`MINSD` (Intel source-wins semantics as MAXSS), `BSWAP`. **Loud check, translate time**: `loud_unhandled()` turns any other `/*UNHANDLED*/` into `__builtin_trap();` (the cache hints `PREFETCH*`/`PAUSE` become `/*IGNORED*/`); `gen_translated.silent_unhandled_sites()` refuses to generate a layer with a member still holding the marker. `UNHANDLED_DEAD_NOISE` lists the only two such functions (`0x140480030`, `0x1404B6ED0`: FADD/FILD/FDIV/OUT/OUTSD after the function's last reachable ret/int3/unconditional goto, behind no label a reachable branch targets: read in the generated code, INF for a full reachability proof).
- **Mirrors of import models** (`pes_stubs.hpp`, `xlate.import_model_lines`): once the hash was right the write logs still differed at 168 bytes: the harness runs the models' machine code, whose scratch registers a caller spills. `pes_model_vsprintf_s` now leaves rcx, rdx, r8 (= last writable byte), r9, r10 (= buffer), r11 (= va cursor) as `vsprintf_model.s` does; `pes_model_memcmp` is a transliteration of the `code_hex` (registers: rax, rcx = differing byte/qword or bswapped b qword, rdx = b-a, r8, r9); `memchr` updates rcx and r8. Flags are not mirrored (no caller reads them after a call).
- **Harness (`snapcase.py`)**: `0x141B6FE20` does `mov word [rsp+0x60], 0x100` then `mov rax, [rsp+0x60]`; the slot held a stale return address in PES (real bytes) and 0 in the translation (it pushes 0). A write that only partly overlaps a return-address slot now zeroes the slot first, so the harness equals the translation in the uncovered bytes. Earlier proofs read such a slot only in full, so none changes (INF: not re-run).
- Layer: `results_proccam.json` record for `0x141F7AE60` (5 calls: live2/pid3234533 seq6218/6219 scene start, seq6220/6224/6228 proc_camera; `synth_ctor.py` states), `closure_proccam_ctor.json` (the 76 snapdiff members minus the two allocator natives `0x1403FBC10`, `0x141B34CB0`), +32 functions.
