## 1. FUN_1406d01d0 is not a "turn-lock eligibility" test (CONFIRMED, asm `a_1406d01d0.txt`, decompile `d_1406d01d0.c`)

It is a GOTO_RUN entry variant (callers: GOTO_RUN `0x1406be4bc`, STEP_TURN_RUN `0x1406c7c1c`): it picks one of the turn rows 0x56f / 0x570 / 0x571 / 0x572 (or the goto-row table's row, 0x565 for a tired man), issues it, writes the request words (class, speed words, 0x20/0x24/0x1d/0x22/0x1f/0x17/0x18, state 7) and returns 1; it returns 0 on a precise request or a motion outside 0x8ac..0x8b1 (not 0x8af). The old `TurnLockEligible` stand-in returned true for every motion in range and wrote nothing else. Replaced by `pes::EnterGotoTurn` (`src/pes/movestep_turn_entry.{hpp,cpp}`; each compare cites its VA); the stand-in, its declaration and its test stub are deleted; callers: GOTO_RUN (one line in movestep_run.cpp, StepLand2 told) and STEP_TURN_RUN.

The tail (FUN_1406b8340) applies them. The family's direct `host.Issue(...)` calls in group B bypass the request; and `kHitFrame/kHitMotion` (0x28/0x27) are written from `MotionStartTime`/`PhysiqueG` in EnterGotoRun, where PES copies the same hit seconds (FUN_1406e7920 = (blend or cancel ticks / 54) / playback) and distance (FUN_1406e7730, needs FUN_1406af6d0/FUN_1406af9a0, untranslated).

## 2. The proof tool: `tools/dev/translate/handler_oracle.py` (CONFIRMED)
Replays one real rendezvous capture in the unicorn harness with a hook on every `call` of the handler's body and logs, in order, target, argument registers/XMM, the 32 bytes behind each pointer argument before and after, and the result; plus the request block at entry and exit, a context dump and `--probe` reads. `--perturb SPEC.json --count N` redraws request words and poke addresses before the run: callees still run PES's bytes, so every host answer is PES's own for that input (rows labelled SYNTHETIC inputs, PES answers). `tests/pes_movestep_turn_entry_test.cpp` feeds the port a host that answers ONLY from the rows (`tests/movestep_unbound_host.hpp` aborts on any other read), then compares every request word, the return value, the random draws and the analyser call. Rows are PES-derived and never committed (`GF_PES_STEP_ORACLE=<rows file>`; skips without).
Run: 6 real calls (`live2/pid3332804/seq089,281,418,487,540,551`, unpacked by zstd into scratch) + 1,272 perturbed rows (3 spec files, 60/150 draws per capture): **1,278 cases, 1,053 entered (return 1), 225 refused, all 432 request words bit-exact, every Percent draw and the analyser call equal.** Real-call coverage alone is thin (5 of the 6 calls return 0; only seq089 enters, via the phase-1 carrier arm): the perturbed rows carry the arm coverage. Unobservable by this test: AbilityWeight's ability id (the host answers the byte solved from PES's weight), RecordTicks/AnimeRecordClass values the rows never vary.

Resume: the ring is the root-motion predictor family's output (FUN_1406e9800 reads it); hook a P-class tick and diff two snapshots, or run the anime layer (AnimeLayer5) which owns FUN_141eb3bd0 / FUN_141eb3af0.
- **"Speed ring" pl+0x3FC (item 3): the premise is wrong.** `FUN_140a75be0` reads `pl.f32[+0x3FC + 16 * pl.u8[+0x108]]`, but `pl+0x108` is a BOOL, written by FUN_140a750a0 (`*(pl+0x108) = (*(pl+0x109) == 0)`, 0x140a75xxx end of function), not a ring head: the table is the AI record's PATH list (count at +0x3f4, entries of 16 bytes at +0x3fc, first dword = the waypoint's speed in km/h). `FUN_140a75030(pl, pt, w, 0)` appends a waypoint and sets the new entry's speed to 16.0 (0x41800000); the list is built by the AI path planners (FUN_140a76440 is the per-man updater that resets it: it clears +0x3f4/+0x3f5/+0x3f7 and the +0x108 byte; FUN_140a750a0 resamples it). So the loose presser's command speed is the speed of the path entry its press planner wrote (16.0 for a point added by FUN_140a75030 -> class 3 by FUN_140a75be0's ladder: 13.5 < 16 <= 22), not a ring; GF's instantaneous `GetMovement()` sample flips 8.0/13.5 because it is not that. NOT wired: needs the press planner's waypoint writer (ai_press_*, PressAI) before the `elizacontroller.cpp` stand-in can read a list.
