## 2. What changed

- **`pes::ToGodotCamera`** (`src/pes/fixdemo_camera_rig.*`): the PES->Godot pose conversion as a pure function (z = normalise(eye - target), x = up x z, y = z x x, vertical fov = fovRad * 180/pi, no axis change: Fox space is Godot space). `PesCutsceneCamera::update` calls it (same maths as before: **the conversion was not wrong**; it was untested). Tests (`ProcCameraGodot.*`, no install needed): the captured frame-0 pose centres its target (|x|,|y| < 1e-4, depth > 0), basis orthonormal and right-handed (x cross y = z), pose up is picture up, a point 1 m toward -z of the scorer is on the picture's right (pins "no mirror"), fov unit (rad->deg), frame height at the captured distance is 1-2 m (a torso shot: 4.19 deg vertical at 18 m, a rad/deg or horizontal/vertical slip would break it). Mutations run, rebuilt, reverted: **M1** mirrored x (`cross(z, up)`): the handedness test fails; **M2** fov left in radians: handedness and frame-height tests fail; **M3** (EngineCovers ignoring other stages, since deleted) failed its test.
- **The abort is now a failed frame.** `FixDemoCameraRig::Step` returns `std::optional<ProcCameraPose>` and runs the engine under a `longjmp` recovery installed through a new `pes_dispatch_missing_handler` (declared in `pes_dispatch.hpp`, defined and called first by `pes_dispatch_missing` in the generated TU; `gen_dispatch.py` emits it; only `pes_dispatch_gen.cpp` changed, +2 lines; without a handler it aborts exactly as before). `PesCutsceneCamera::advance` drops that camera, `push_error`s the missing VA ("procedural camera 0 stopped: ... untranslated 0x140892100; the broadcast camera stays") and `update()` returns false so `match.gd` keeps the broadcast camera. `ponytail:` in the header names the removal condition (closure covers the engine). Test `ProcCamera.AnUncapturedRecordFailsTheFrameNotTheProcess` (record with stage 1 at 0 -> `Step` empty, `*missingVa == 0x140892100`, then a camera of the captured record on the same rig still ties PES's first frame). I did not run a mutation that removes the handler (it would abort the test binary): **not mutated**.
- `match.gd`: bone names were `sk_head`/`sk_root_hip` (not GF bone names: `find_bone` = -1, "Index p_bone = -1" errors every logic frame); now `head`/`hip` (`src/rig/rig_names.hpp`). `--fdc-target N` feeds the debug track's procedural camera a GF player as the target. Skeleton heights of those bones vs PES's 1.595/0.941 m: **not checked** (no frame reached the engine's output).
- Tests run: `pes_proc_camera_test` 5/5 (3 ProcCamera + 2 ProcCameraGodot; the earlier 3-frame bit-for-bit tie and `TheTargetFollowsTheActor` still pass with `Step` returning optional). Full build of the merged tree under load: 4,922 steps, 41 min (the `pes_dispatch.hpp` change rebuilds every TU).
