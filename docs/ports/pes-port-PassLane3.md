## 2. M6: the sqrtf stop (CONFIRMED root cause, fixed)

- Root cause (CONFIRMED): `frame_trace.run_recorded` built its LazyMap with `models if models is not None else (load_import_models() if trace is not None else {})`. A plain run (no `--out`, no `models=`) therefore had an EMPTY import table, so every ucrtbase/VCRUNTIME export (int3-filled) stopped the run, whatever the import model table said. The sqrtf model (`import_stubs.json`, `f30f51c0c3` = `sqrtss xmm0, xmm0; ret`, commit 41f83d6fb) was already in the tree and was unreachable from plain runs. The writer's `jmp [slot]` thunk `0x1415A1780` does reach the export in seq206 (CONFIRMED by the stop).
- Fix: `frame_trace.import_models_for(models)` = the caller's table, else `load_import_models()`, used by `run_recorded`. Trace-mode callers already got the table, so their behaviour is unchanged.
