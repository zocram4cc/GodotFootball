## 1. Where the dribbler's touch chain stops (CONFIRMED by probes, seed 7, pes-loop, 120-160 k dribble ticks)
Main's hypothesis (the issuer FUN_1406B4580 / FUN_140425010 / kick application 0x140870A40) was checked and is NOT where it stops:
- `FUN_1406B4580` is a 3-instruction thunk (object at P+0xC40 via `FUN_1406D9010`, its vtable +0x68). The dribble tick calls it only for the action-switch requests 0x52/0x53/7 (`0x1407B37D0`, `0x1407B05F0`): it asks "may I switch action", it does NOT touch the ball. `FUN_140425010` is called from FUN_140425A90 / FUN_140581D40 (ball side), never from a dribble sub-state.
- A dribble touch is the SAME per-frame body scan as the trap's: `0x1406EDCE0` runs the action's slot +0xB8 (dribble: `FUN_1407B7720`) only when P+0x2460 bit 9 (contact pending) is set. In the whole dribble region the ONLY writer of bit 9 is `0x1407A7085`, inside `FUN_1407A6F30`, called from the sub-state handlers `FUN_1407B05F0` (call at `0x1407B11EA`) and `FUN_1407ACB70` (`0x1407ACC94`), and only when `FUN_1406EC260(P, contactFrame)` holds: the issued motion `P+0xAE0` must be IN THE MOTION TABLE (P+0x354, ten 0x14-byte entries rebuilt every tick from the clip GF PLAYS, `RebuildMotionTable`) with its elapsed seconds on the contact frame (`FUN_1406EC2A0`, `FUN_1406E68C0`).
- GF never plays what the dribble issues. Probe over 160,000 dribble ticks (`TMPHIST`, removed): `P+0x2460` bit 9 was set at 0 ticks, bit 10 at 0 ticks; the table was EMPTY (`P+0x420` = 0) in the dominant keys and never listed P+0xAE0 (`tblSelf` = 0 in every top key). The issued motions are PES `dribblerun_*` / `dribble_*` clips (0x220 `dribblerun_2_3_135_in_cp`, 0x226, 0x248, 0x24B, 0x27A, 0x262, 0x26E, 0x281, 0x32C `dribble_0_3_000_near_sole`, 0x368 `dribble_guardside_...`): no clip family in `pesclips.cpp` carries them (families: dodge, tackle, locomotion, trap), so `PlayIssuedClip` has nothing to play, and the runner does not call it at all.
- So the chain stops one step BEFORE the issuer: PES's SetMotion (`FUN_1406F0F70`: P+0x3B50 motion, +0x3B54 start, +0x3B58 mirror, +0x3758 rate, `P+0x375C = 1`; the series variant `FUN_1406F14E0` sets `P+0x375C = 2`, `P+0x3B50 = -1`) runs inside the dribble tick, but the body keeps GF's clip. P+0x375C has no reader anywhere in the image's code (image scan of every `[reg+0x375C]` access: 4 writers, 0 readers).
- `RunPesBodyScans` also runs only for AC8 == Trap, so a dribble contact would never be scanned either.
