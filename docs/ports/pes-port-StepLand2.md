## 1. What was wrong in GOTO_RUN (every item CONFIRMED from `a_1406bdf10.txt`, pinned by a test, red on the old code)
The decompile loses every `FUN_14043a0a0` argument and the XMM registers that carry across the function, so the port was transcribed from the asm. Defects of the old port, by address:
- **The clip end.** `R12D` = FUN_1406b1d00 (the clip's end tick). The port never read it: it used the first hit tick (`hit0`) where PES uses `R12D` in the re-entry (`0x1406be3b3 CMP EBP,R12D; JGE`), the lock window, the stop arm and the classification. Also `R12D` is OVERWRITTEN at `0x1406be17c` with `int(tps*8/60+0.5)` when the live bucket req[0x20] is 0 or 5 (and the hits shift for a run-step clip); the port tested the move bucket req[8] and used `PickN(1)` for the draw.
- **Re-entry** (`0x1406be380..0x1406be3fa`): body direction |FUN_14043a0a0(req[2], req[4])| > 45 OR |req[6]| > 45 (ANDPS abs) OR the command flag BYTE at request byte offset 0x3f. The port tested `turn` (signed), the facing error req[7] and WORD 0x3f's low byte (the turn lock's direction).
- **Turn-lock window** (`0x1406be21b..0x1406be244`): `total <= frame < (total + 2 end) / 3`, no `+1`; stores the lock heading as a float in word 0x3d (the port stored `uint32_t(heading)`), ticks `int((end-frame)/F2468 + 0.5)`.
- **Stop arm bucket** (`0x1406be5f6 MOVAPS XMM1,XMM7`, XMM7 = FUN_14043a0a0(req[2], req[4]) from `0x1406be392`): the bucket of the signed body-direction difference; the port used the stamp's bearing. The arm reads `end*scale > frame || frame < total` (not `hit0`), is skipped for FUN_140a6e260's motions {0x8bc, 0x8c6, 0x8ce..0x8d0} (now ported) and has a first sub-arm (`req[0x1a] < 0.1`, precise 1, band 3, class < 2: speed word 5, class word 0, re-plan) the port lacked.
- **The turn / end-of-clip arms** (`0x1406bee16..0x1406bf032`, `0x1406bed3b..0x1406bedd7`): the ground-speed ladder (5 / 11 / 16) into STEP_TURN_RUN, the `|req[1]-req[3]| > 45` / `dist3` / `1.0` gate into the rate ladder (0.15 / 0.3 / ceiling) + RUN_TURN_STEP + the run entry, else the displacement's forward speed into RUN_TURN_RUN or a re-plan under 8 km/h. The old port had one merged arm.
- **The straight re-plan** (`0x1406be83f..0x1406bec79`): share by the jump table at `0x1406bf088` (20 motions), the facing step limit 157.5/tps (112.5/tps above 13.5 km/h forward, 135/tps for the stand turn, turn clips and run steps), the ready/ACCELERATE classification (`0x1406beac7..0x1406bec55`, all four band/class arms), and the run entry's rate clamp (`0x1406bed0e`: above the ceiling takes the ceiling, not 0).
- **Byte reads.** `CMP byte ptr [RSI+0x3d/0x3e/0x3f]` in RUN_LOOP (`0x1406c01f4..0x1406c0216`), STOP (a_1406c9e20) and the re-plan entry (d_1406ce820.c 238, 328) read the command's flag BYTES (`req.FlagAtByte`), not words 0x3d..0x3f. (GF's fill never sets those bytes, so they read 0; the ports now read the right place.)
- **RUN_LOOP arm 3** (`0x1406c0321..0x1406c0387`): the look distance req[0x12] against 3.0 (not req[0x11]), and |req[6]| for both turn gates (the port compared signed turns).
