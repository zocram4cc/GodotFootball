## 1. Decode (CONFIRMED unless marked)

**The list builder is inside the cut start `0x141F2DD80`** (called from the player's step `0x141F2F6B0` state 4 and from `0x141F41CC0`). It resets the list (`player+0x90 = +0x88`, `+0xA0 = 0`), then, `sets = player+0x7C`:
`h = word % sets`; for tens group `t` = 0..9 of set `h` (vectors at `player + (set*10+7+t)*0x18`): if `n > 0`, `i = 0x141F7A100(scene+0x178, n)` (no scene: `i = 0`), `r = vec[i]`; `r` is pushed when the list holds fewer than two entries or `r.start (record+0xC of the map value) > back.start`. The vectors are filled by `0x141F3CFA0` from the record map `+0xB58`: `key/100 < 10` is the set, `(key%100)/10` the tens group; tens 0 also zeroes `node+0x34`; `+0x7C` = the number of leading sets whose tens-0 vector is non-empty. The rest of `0x141F2DD80` (placement, step length draw `0x141F7A150(scene+0x128, 100)`, actor height rescale `0x141F7F840`) is unrelated to selection.

**The draw `0x141F7A100(rng, n)`:** `w = (RangeRaw(rng, 0x2AC, slot 2) + rng[+0x20] + 0xAA) & 0x3FF; rng[+0x20] = w; return w * n >> 10` (disasm `0x141F7A112 mov edx,0x2AC; 0x141F7A123 add r8d,0xAA; 0x141F7A12D and eax,0x3FF; 0x141F7A13D shr eax,0xA`). `RangeRaw` is `0x140A924E0`, i.e. `pes::Random::RangeRaw(2, m)` of `pesrandom.hpp` (`(float)state * 2^-31 * (float)m`, truncated). `0x141F7A150` = `RangeRaw(rng, m, 2)`.

**The set word writer is `0x141F5D2E0(mgr, player, index)`** (called from the step machine `0x141F59380` at `0x141F596AD`, `0x141F5995D`): `word = 0x141F7A100(mgr+0x150, 100)` (generator **R1**, not R2); then the byte `mode` = player's map `+0xAE8` key 0, value `+0x48`: mode 0 keeps the word; mode 1 takes `mgr+0x1A0`; mode 2 with `prev = mgr+0x1A4`: `if (prev < sets && sets >= 2) { m = word % (sets-1); word = m < prev ? m : m+1 } else word %= sets; mgr+0x1A4 = word`; then `*(player+0x78) = word`. All 16 captured layers have mode 0 (`+0xAE8` map values read: `probe2.py`, scratch), so the captured words (31, 66, 85, 35, 82, 58, 43, 97, 76, 75, 78, 52, 79, 45, 49, 71) are plain R1 draws below 100. The mode's loader is not located (INF: a layer header field).

**The seed chain of the scene generator `scene+0x178` (the scene constructor `0x141F55110`, lines of its decompile 44-112, disasm `0x141F55200..0x141F5543B`):**
1. A = `scene+0x128` (a `math::Random`, vtable `0x142BA5668`, defaults `0x2F3D0..`): `slot2 = G.draw + 1` where `G.draw = 0x141F50160(ctx, 20000) = 0x141F7A150(global generator 0x1437F5D90, 20000)`; then `A+0x20 = RangeRaw(A, 0x400, 2)`.
2. R1 = `scene+0x150`, R2 = `scene+0x178` (the 2-element array of `0x141F55A10`-constructed generators, stride 0x28): each `slot2 = 0x141F7A150(A, 20000) + 1`, then `+0x20 = RangeRaw(self, 0x400, 2)`. R2 is the builder's generator.
3. `scene+0x1A0 = 0x141F7A100(R1, 100)`, `scene+0x1A4 = 0x141F7A100(R1, 100)` (`0x141F5541F`, `0x141F55436`).
4. The global generator `0x1437F5D90` is seeded in the context constructor `0x141F4C950`: `0x141F51FD0(clockValue % 10000)` where `clockValue = 0x141B34AD0(0x141B34A30())` (a clock read): `slot2 = (arg ? arg : 1) + 1`, `word = RangeRaw(0x400)`, then 11 draws of `RangeRaw(16)`. So PES's scene sequence is clock-seeded and not reproducible from the image; the draw count the global has made before a scene is session history (INF: one draw per scene from the scene constructor).
Capture evidence: the R2 states of the 16 captured players differ per layer of one scene (post-build states), while A's `+0x20` word is constant per scene (A is only drawn with `0x141F7A150`), as the chain above says.

**The record in force per layer** is `list[player+0xA0]`, advanced by `0x141F42110`: while the clock `player+0x80` has reached `list[idx+1].start` the index steps, and `0x141F39CC0(player, list[idx])` applies the record to the layer's FixDemoCamera (`player+0xC68`, `camera+0x130 = record+8`). From the first call the list's first record is applied, whatever its start. When the list is exhausted `0x141F36000` deactivates.

**Fix made on the way (committed):** `tools/dev/translate/full_snapshot.py`: `capz.py unpack` restores a full capture's zero pages as sparse holes, and `SnapMem` read every hole as "a page a slim capture dropped", so any replay that allocated from a never-written heap page was refused (`case excluded: page not captured`). ## 4. The cross-layer choice `0x141EB0570` (CONFIRMED decode; the choice OPEN)

`0x141EB0570(holder, camera)` maintains a global list `0x1437F4A08` of camera holders: setting a non-null camera moves the holder to the tail (the current camera of the renderer is the tail's holder); setting null removes it; the previous tail is deactivated (`holder+8 = 0`). Its two FixDemo callers are `0x141F35F70` (activate: copy the broadcast camera's parameters into the scene camera `scene+0x260`, set it as `scene+0x258`'s camera; once per player, guarded by `player+0xADC`) and `0x141F36000` (deactivate). So it activates the **scene's single camera**; it does not pick among layers. Each layer's FixDemoCamera (`player+0xC68`, per-layer, constructed in the player's state 3) has its own pose engine `0x141F7BFE0`, called from `0x141F7B770` (FixDemoCamera vtable `0x142BB0D90` slot 4 = `Update(params)`, return address `0x141F7B7FA` in all 32 captured calls) with the shared params block `0x1437F4A40`: the layers' cameras write one block, so the arbitration is the update order of the camera objects. INF: the later-updated one wins. Which object calls slot 4 on which cameras each frame is not decoded: **OPEN** (needs the caller of vslot 4 over the camera list, or a capture hook on `0x141F7B770`).
