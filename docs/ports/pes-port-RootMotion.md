## 3. GF code
- `PesWorld::StepAdjusters(slot, degToRad)` (pesworldrecord.cpp) replaces TrapContact2's `RunTrapAdjuster` C++ wrapper: it runs the translated `pes_fn_141EB3AF0` on A, the height and the yaw adjuster of the man's P in the window, in PES's order, over the window's anime chain (P+0xA08, O2+0xD0 = the man's position, which the actor writer stores each tick). The A step is `A+0x14..0x1C - O2 point` (PES's step adds to the layer's root point). The yaw step is `P+0x4F0`. The old `ponytail:` on FUN_141EB3AF0 is gone.
- `PesWorld::ArmYaw` (translated FUN_141EB35A0 then FUN_141EB3AE0) and `SetRootFacing` (P+0x20 = angle, then the one-tick arm: FUN_141EB56D0's param_3 == 1 path).
- `pes::movestep::ApplyBodyTail(host, req)` (movestep_dispatch_seams.cpp): FUN_1406B8340's body tail, in PES's order (root-facing write, then the yaw arm from req[2] to req[0x3d] over req[0x3e], flag byte req[0x3f]). `MoveHost::SetRootFacing` / `ArmYawAdjuster` are new pure virtuals (UnboundHost aborts on them; the four test hosts record or ignore). `pesmovestep::ProcessMoveStep` calls it after Dispatch and before the due issue.
- `pesmovestep::StepAdjusters(player, match)` runs from `Player::Process` right after `ProcessMoveStep` (PES: the anime tick of the same frame): A's displacement `WarpRoot`s the body (as TrapContact2 did, now for every man), the yaw step `TurnRoot`s it. The old per-trap call in `RunPesTrapTicks` is deleted.
- `HumanoidBase::TurnRoot(yaw)`: WarpRoot's turn, and the clip's remaining root path and the predicted next start turn about the point reached.
- **The two GF worlds mirror the yaw sense**: the trap world's facing is `atan2(x, GF y)` (the translated trap start arms the adjuster in it) and MOVESTEP's is `atan2(x, -GF y)`; the adapter converts every angle it hands the adjuster to the trap sense (`180 - movestep`) and applies `-yaw` to GF's counter-clockwise yaw. Wrong in any one of the three places and a turn runs the wrong way; the test below measures it.
- `PlayIssuedClip`'s rotation zeroing is NOT removed: `rotationSmuggle` is a GF mechanism PES does not have; PES's rotation is the adjuster's, which is now applied.
- Stand-ins left (each `ponytail:`): the height adjuster's output (+0x18) has no consumer (GF's body has no root height); the engine step `chain.vt+0x38` and EEDF0's request block are not consumed (EEDF0 is proven but not run in GF: its output has no reader); P+0x20 is re-synced from the man record each tick and the root facing write turns the body at once (INF: the engine's readback of the root yaw is not decoded); the A modes 2 and 3 (approach, FUN_141EB26F0) are never armed in GF (the MOVESTEP tail's local_65b / local_650 words are not written by any ported handler) and stay loud aborts if reached.
