## 3. Type-13 frame advance (ticket item 2): NOT ADVANCED, precise reason

Tool: `tools/dev/translate/type13_advance.py` (committed). Frame 1 is the recorded call; frames 2–N re-enter the body on the same memory with the captured register file. The caller's per-frame loop is not emulated (INF: the body alone).

Real captured state, 3 frames each:

| capture | record kind at `r8` (dword) | result | `inc [rsi+0x1198]` at `0x140A128E4` | gate `0x140A0E690` | exit `0x140A1282C` | writes outside stack |
|---|---|---|---|---|---|---|
| seq014 | 0x2F (47) | `rax=0x2E`, clean return | not reached | not reached | not reached | 0 (88 stack bytes) |
| seq015 | 0x24 (36) | `rax=0xB`, clean return | not reached | not reached | not reached | 0 (104 stack bytes) |

Determinism (CONFIRMED): seq014 three runs byte-identical; the frame-by-frame results repeat exactly.

Reason (CONFIRMED from disassembly and the emulated trail): the body does `mov eax,[r8]; dec eax; cmp eax,0x24; ja <epilogue>` (`0x140A115FC`–`0x140A11609`). seq014's kind 0x2F exceeds the table and returns at once. seq015's kind 0x24 dispatches to a case other than the type-13 case and returns without the increment. Neither capture runs a type-13 record. So the frame counter and positions cannot advance from these captures. The hook name `type13_body_A115E9` is a misnomer: the body is the dispatcher for many record kinds.

What-if (not the real state), `--record-kind 13` from frame 2 (frame 1 stays real): frame 2 enters the import thunk `0x6FFFFFBC73B0` and loops to the instruction budget (`did not return`). The recorded runner has no import models, so this is the same unmodelled-import blocker. No frame counter is reached.

Writers (ball, S4): not reached by these calls (writes are stack only). Writer naming is OPEN (`pes-re-type13.md` §4).

Open: find a capture (or a live state) where the body receives a type-13 record and the roster gate `0x140A0E690` passes; the earlier forged-record notes say the gate fails at rest.
