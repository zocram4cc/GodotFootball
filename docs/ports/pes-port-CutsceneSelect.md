## 4. Selection contract (ticket item 3)

Chain, with what is proven on live calls (CONFIRMED unless marked):

1. **Event → scene id.** Foul/card: the sanction tree `0x14047F170` returns the scene id in rax (§2; PES-bytes replay). Builder `0x140480910` copies it into the request `req+0` and handles `0x20022` as "free and return" (sanction doc item 1, CONFIRMED gate at 0x140480A8B–0x140480AAC). Goal: pool pick by `FUN_140A92530` over the goal context `+0x108` (pes-re-scene-choice.md §2a, OBS; not replayed here). Period end: `0x140488470` (table above). Substitution `0x140484A10` and end-of-match `0x14048AB10`: fixed constants or a state machine (pes-re-scene-choice.md §2b; not replayed here).
2. **Scene id → T2 scene.** `table_<cat>.bin` scene `index = (id & 0xffff) − 1` (`FUN_140a7c800`, OBS). Resolved by `scene_map.py`.
3. **T2 steps → cut refs.** Each step's `cutRef` (a T1 cut group id of the same category); `cutRef == 0` terminates. `FixDemoList` `FUN_141f616f0` expands each step into a 0x1E0-byte play step (pes-re-cutscenes.md §4.2 step 2, OBS).
4. **Cut ref → variant row.** `FUN_141f4fda0(cutRef)`: per-manager cache `std::map<cutId,rowIndex>` at `+0x30`; on a miss calls the matcher `FUN_141f4b1d0(mgr, cat, rows, nRows, history=0x1437f5dc0+cat*0x40)` (§4.2 step 3). **Matcher `0x141F4B1D0`: PROVEN 4/4** (§1). Evaluator `0x141F4D2F0`: **PROVEN 4/4**. Caller `0x141F41CE0`: PROVEN 18/18. The variant-pick wrapper `0x141F4FDA0` itself is not in the hook set; not replayed here (OPEN).
5. **Row → `.fdc` set.** The row's `fdc[0..9]` (the layers that play together) and `b0`, `f`, `b1` (copied into the play step at +0x68/+0x6C/+0x70, OBS).
6. **Load and play.** `FUN_141f36200` loads each `.fdc` (type switch on the record kind; PROVEN 0/2 here: blocked). Slot build `FUN_141f5f330`: **PROVEN 18/19**. Human create `FUN_141f57840`: PROVEN 1/4 (3 blocked by the import page). Human records go to a map keyed by slot (`FUN_141f3e830`), camera records keyed by their +0x00 key (`FUN_141f3dd00`) (§4.2 step 6, OBS).

What the matcher decides, per row: the first accepted value in priority order per key column (`FUN_141f4d2f0`), or a random threshold (type 0x19) or weighted roll (type 0x43) through the `Random1000` generators (§4.2, OBS). The translated matcher and evaluator are bit-exact on the captured calls, so the choice logic is verified on these inputs; the RNG seeding of the live match is still not traced (OPEN, pes-re-scene-choice.md §3).

**Not proven in this pass:** the link from a live matcher call's input cut ref to its output row (needs the `call.bin` argument decode of `141F4B1D0`, which this pass did not do); goal and end-of-match selection on live calls; the foul-slot → match-player remap (cutscene roles doc §7 item 5, OPEN).

## 5. Hybrid input spec for the Godot layer (ticket item 4)

The translated selection (GF core) fills one `FixDemoSceneRequest` per queued scene and hands it to Godot. Godot consumes only this struct and the install's `.fdc` / `table_*.bin` files. Values are not copied here: the install supplies them at runtime through the VFS.

```
struct FixDemoSceneRequest {                 // one per scene request queued by an event builder
  uint32_t scene_id;                         // (cat<<16)|(index+1). Source: rax of 0x14047F170 (foul) or
                                             //   the builder's constant (period end 0x140488470, sub 0x140484A10,
                                             //   end 0x14048AB10); foul builder 0x140480910 writes it to req+0.
  uint8_t  category;                         // (scene_id>>16)&0xff. VA: matcher arg, FUN_141f4b1d0 param_4.
  uint16_t scene_index;                      // (scene_id&0xffff)-1. VA: FUN_140a7c800. Index into table_<cat>.bin T2.
  bool     no_scene;                         // scene_index >= T2 count, or scene_id in {0x20022,0x50010,0x7002b,0x301b6}.
                                             //   Godot plays nothing and the hold still runs (sanction doc §1).
  uint8_t  step_count;                       // T2 steps before cut_ref==0. VA: FUN_141f616f0 (FixDemoList).
  Step     steps[step_count];
};
struct Step {                                // T2 row (0x38-byte runtime row; table field order, pes-re-cutscenes §2.2)
  uint8_t  kind;                             // world anchor selector. VA: switch in FUN_140476c50.
  float    fade_s;                           // T2 f32 "fade" (seconds, INF). Default 0.5 in FUN_141f616f0.
  uint32_t cut_ref;                          // (cat<<16)|(group+1). VA: resolved by FUN_141f4fda0.
  uint32_t flags;                            // scene attribute bits (goal selection, FUN_140a7c800). Not needed for playback.
  uint16_t w0; int16_t w1; int16_t w2;       // timing, 60 Hz ticks (w2 = -1 means unset). Copied by FUN_141f616f0.
  uint8_t  trip[10][3];                      // copied verbatim into the play step; meaning OPEN.
  uint16_t keys[10];                         // variant condition keys (condType<<8|value). Matcher input.
  uint32_t b0; float f; uint32_t b1;         // row fields; copied to play step +0x68/+0x6C/+0x70 (FUN_141f616f0).
  // The chosen row's layers (fixed by FUN_141f4b1d0 for this context):
  // fdc[0..9]: cut_data/<name>.fdc under cpk_dat/common/demo/fixdemo/<cat>/cut_data/
};
```

| `scene_id` (period end) | builder | `0x140488470` | OBS (pes-re-scene-choice §2b) |
| `category` | `(id>>16)&0xff` | `FUN_141f4b1d0` param_4 | OBS (cutscenes §4.2) |

Godot-side consumption (what the hybrid layer does with the struct; not translated, per owner ruling 26-10-26):
- **Camera tracks:** `Camera` records of each `.fdc` (`FUN_141f36200` type switch), keyed by +0x00 (`FUN_141f3dd00`), times in 1/60 s.
- **Actor binding:** `Human`/`Object` record +0x00 (u16 slot). Slot ranges per cutscenes doc §0: 0–10 home side (0 = subject in goal), 11–21 away, 22–25 officials, 26 coach (goal). The slot→match-player remap is OPEN (roles doc §7 item 5).
- **Timing:** `kind` selects the anchor; `fade_s` the transition; `w0/w1/w2` the step durations in ticks; the scene duration is `FUN_141f5ec60(sceneId)`.

Acceptance check for the spec: every `Step` built from the install table matches the script's chain for the same scene id (the script output is the oracle for the table side; the replay verdicts are the oracle for the code side).
