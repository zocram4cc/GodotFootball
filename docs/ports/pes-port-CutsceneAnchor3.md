### What 0x14047DF00 does (CONFIRMED by disassembly and decompile)
With X = rdi (the object):
1. `0x140A923B0(X+0x18, edx=2)`: a member initialiser (translated in this round).
2. Zeroes X+0x0 (dword), X+0x4 (word), X+0x8 (dword), X+0xC (word), X+0x12 (byte flag candidate), X+0x50/0x58/0x60 (qwords), sets X+0x10 = 0xFF (dword).
3. Stores the vtable 0x14259C9E0 at **X+0x40** (the sub-object) and zeroes the sub's flag at X+0x48.
4. If the flag is 0: `rax = [vt+0x10]()` (0x14044E0B0, returns &0x14259C9F8, a name), `rdx = [vt+8]()` (0x140419D40, returns &0x142596908, a name), then `0x140451C10(sub, rdx, rax)` (the named-object registration), then flag = 1.

So the sub-object of the goal DemoInfo A0 (A0+0x158 = X+0x40 with X = A0+0x118) is exactly this object, and its flag (A0+0x160) is 1 once the constructor has finished. This matches the seq203 dump (A0+0x158 vtable, flag 1).

## 5. Where the wide test stops now (CONFIRMED by run and gdb)

`0x14047DF00 -> 0x140451C10 -> 0x141B55730` (the registry find-or-create, decompiled: `dec_141B55730.txt`):

- **Not found** (lVar3 == 0): callback `0x140421F40`, then the factory `0x140440FC0` (`param_6`): it allocates a 0x20-byte object with vtable 0x14259C940 (refcount 1, +0x10 = a 0x174-byte block from `0x140441320`), stores it in `*param_3` (= X+0x50 = sub+0x10, the node PES holds there), then `insert` (vslot +0x68).

GF stops at the factory: `PES_DISPATCH_UNTRANSLATED: 0x140440FC0`. The factory is not proven (PES never ran it on seq203: its name was already registered). Its next step would be `insert`: GF's `PesCameraRegistry` (pes_native.cpp) aborts on insert by design (`pes_native_registry_insert` Die), and its find answers only `CAMERA_TARGET_GGSS` names.

So the blocker is not the constructor any more. It is the **registry**: PES's name registry is generic (GameImpl's), GF's is the camera table. The DemoInfo's names are registered once (at construction in PES; probably at boot, section 2), and the else arm's list then reads the registered factory output (N1).
