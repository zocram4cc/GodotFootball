# LedgerCredit: the translated/diffed join, and a progress history (18-11-26)

Branch `LedgerCredit` = `61c00e0b82db9012a7ab276fad8ed974fe8c1e66` (on top of main `1da063ca5d`, which holds the red tests). `git ls-remote origin LedgerCredit` confirms it. Author zocram4cc.

## Why the translated layer never reached the ledger (CONFIRMED)

Three independent defects in `tools/dev/ledger/joins.py` and `ledger.py`, measured on the committed data:

1. **Only one results file was read, and only its `diffed` boolean.** `--pilot` took one path (`tools/dev/translate/results.json`). Records in `results_core`, `results_presentation`, `results_cutscene`, `results_impure`, `results_trapaction`, etc. never joined. Records proven by snapshot (`proven: true`, no `diffed` key) were never counted as bit-exact at all. The committed `joins.json` also had `translated` = 79 VAs, all from results.json.
2. **The VA regex matched only `0x140xxxxxx`.** The image runs 0x140000000 to 0x144FFFFFF. Every doc verdict and every GF source cite in 0x141 to 0x144 was dropped (`decode` had 9,814 keys, all 140; `ports` had 1,840, all 140). Docs cite 0x141/0x142 VAs about 14.7k times. This is why 0x141AF3CA0, 0x141EB3AF0 and 0x141EB5E70 showed `undecoded` with no verdict.
3. **Precedence and the bare run.** Stand-in ranked above any proof. A bare `joins.py` run dropped the spec map and the bridge list, so the next regeneration would have lost them.

## What changed

- `joins.py` rewritten around `build(repo, carried, diff_map, funclist)`. VA regex `14[0-4]xxxxxx`. Reads every `tools/dev/translate/results*.json`: a record is recorded bit-exact when `diffed` or `proven`; `synthetic` is kept per VA (real if any record is real). `translated` = every `pes_fn_<VA>.cpp` under `src/pes/translated` (closure/ included). Bare run keeps the committed funclist and the non-results spec entries; `--funclist` / `--diff` replace/add. `src/pes/translated` is not scanned for cites (its banners name the PES function they translate; that is provenance, not a GF port).
- `ledger.py` classify precedence: inert, out of scope, **diffed** (recorded), **translated** (committed), **stand-in**, **ported**, engine, leaf, decoded, undecoded. RANK: diffed 0; translated 1; ported 1 (a translation supersedes a hand port, so that move is not a regression); stand-in 2.
- Row column `proof`: diffed = `real` | `synthetic`; translated = `record` | `closure`; else `-`. Sub-table column added after status (regression parser still reads status at cell 3).
- **Progress history**: `tools/dev/ledger/history.csv`, one row per regeneration that changes the in-scope counts (`base` = HEAD the regeneration was built on, `date`, `in_total`, `out_total`, one column per status). Seeded from the LEDGER.md committed at HEAD (row 1 = before this change). `ledger.py --check` fails if the newest row is behind the counts. The LEDGER.md summary has the verdict share, the implemented share, the proof split, and one delta line per status.
- `offpath_allow.json`: 107 entries added, see Open items.
- `driver.py` docstring corrected (joins no longer takes `--pilot`).
- `LEDGER.md` regenerated by `ledger.py`, not by hand.
